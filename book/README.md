# 《装机记》· 本源计算机开发史

> **工作标题**，可改。取自那句结论：「问题不在主板设计，在装机——装了六个、漏了一个、还有一个插错插槽。」

一本正在被写的书。记录一件事：**一台「AI 计算机」是怎么从「我发现多开几个终端干活更快」，一路长成一套有 RFC、有一致性测试、有哲学本体论的架构的。**

## 这本书写什么

不是产品手册，不是架构文档（那些在 `2origin-computer/rfcs/`）。

这本书写**过程**：

- 一个念头怎么变成一个工具（opencodex）
- 一个工具怎么逼出一套协议（本象 / 本境 / 影核）
- 一套协议怎么长出自己的哲学（影子与对象、bug 透视镜）
- 以及——**做错的地方**。装错的插槽、查无实据的数字、自己打自己脸的修正

最后一条是这本书区别于一般"技术自传"的地方。**顺风顺水的开发史没人信，也没人学得到东西。**

## 体例（硬规则，写手必须遵守）

### 1. 每个事实必须能指出可复核的 source

这条不是文风要求，是**书的合法性来源**。

它直接来自本境协议的 `source` 规则和 bug 透视镜的自我指涉条款：
**一个专门讲「不要把声明当事实」的书，自己不能靠声明。**

可接受的 source：commit hash · 文件路径:行号 · 可重跑的命令 · 仓库创建日期。
**不可接受**：「我记得」「当时大概」「据说」。

### 2. 三种可信度，必须标出来

| 标记 | 含义 | 例 |
|---|---|---|
| **【实证】** | 有 commit / 文件 / 命令输出可查 | `opencodex` 建仓于 2026-06-19（GitHub API） |
| **【自述】** | 当事人回忆，无外部证据 | 「我发现多终端并行让效率暴涨」 |
| **【推断】** | 作者根据证据推的，可能错 | 「那一周的高强度是因为 RFC 连发」 |

**混用等于骗人。** 自述不是不能写——开发史里最珍贵的往往就是自述——但**必须让读者知道它是自述**。

### 3. 数字现跑现写

见 `../AGENTS.md` 数据背书一节。已经踩过两次：
`RFC-0001` 里「43 条判据」查无实据（实测 38 tests / 97 asserts，无一为 43）；
AGENTS.md 曾长期写着「Conformance 7/7」（实测 5 PASS + 2 MANUAL）。

### 4. 公私边界

素材来自私有仓库、客户排障、会话记录时，**只写现象和原理，不引原文、不贴路径、不带客户信息**。
详见 `../AGENTS.md` 的「🔒 公私边界」。

**判断规则**：一段素材只有在**它本身就是 2Origin / U-King 公开叙事的一部分**时才能进书。
「它很有说服力」「投入很大」都不是理由——**投入越大越可能是核心生意，越不该公开。**

原始研究笔记放**私有仓** `2origin-scratch/研究/`。结论可以公开，**原始清单不行**。

> 2026-08-08 的现场教训：从会话记录挖出 78 个工作文件夹，正要把整张表写进公开的大纲，
> 被拦下。那张表里有竞品调研、API 分发生意、账号风控项目——**等于把整张业务地图发到公网。**
> 用户说的是"你自己去看聊天记录"，**看不等于发。** 这两件事必须分开。

### 5. 内部源必须标明「读者无法复核」

有些 source 只在本机存在（私有仓库、本地日志、会话记录）。引用它们不算作弊——
一本开发史的很多证据本来就在内部——但**必须让读者知道他复核不了**。

| 标记 | 含义 |
|---|---|
| **【公开可核】** | 读者自己能验：公开仓库 commit、可 clone 后重跑的命令、GitHub API |
| **【内部可核】** | 我们能重跑，读者不能：私有仓库文件、本地日志、会话记录元数据 |

**把【内部可核】写成【公开可核】= 又一次把声明当事实。**
凡标【内部可核】的，必须同时写出**产出它的命令**——这样至少它在内部是可重跑的，
而不是一句"我们测过"。

### 关于会话记录：只取元数据

`book/tools/session-timeline.mjs` 从本机 Claude Code 会话记录里提取时间线，
**只读 `timestamp` / `type` / `cwd` / `gitBranch` / `version` 五个字段，白名单式，绝不读消息内容**。

原因很直接：那 589 个会话文件（818 MB）里有私有仓库源码、API key、客户 Device ID、
远程排障时抓到的客户机信息。**原样开源等于一次彻底的泄露。**

要引用某次对话的原话 → 人工打开那一条、脱敏、手抄、标注【自述】。没有捷径。

## 与 `press/` 的关系

`press/` 是**一线报道**——发现发生的当天就写下来，热的。
`book/` 是**史**——事后梳理，冷的，要求前后自洽。

**报道最终汇集为史。** 但报道不能直接当章节用：报道写在事情没定论的时候，
史要在有定论之后回头改写，并标注「当时我们以为 X，后来发现是 Y」——
那个「后来发现」才是史的价值。
