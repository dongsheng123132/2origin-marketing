> **beat（分口）：发现进行时。**
> 别人写已经落地的东西，你写**正在成形的东西**——概念在对话里被想出来、被命名、被推翻、被改派的那一刻。
> 建岗日：2026-08-08。第一篇：可继承授权凭据。

## ⚠️ 两个仓库（2026-08-08 拆分，动手前先看清写哪边）

**线索已迁出本仓**，现在写在私有仓 [`2origin-scratch`](https://github.com/dongsheng123132/2origin-scratch)。

原因：**线索按定义就是未核实的**——原话照录、数字没跑、可能引私有仓素材。
写进公开仓等于把还没验证的东西直接发布，**正是这套方法论要抓的病**。
而且每写一句都要先自我审查，捕捉速度被脱敏成本拖死——**线索是会凉的。**

| 写什么 | 去哪个仓 | 可见性 | 门槛 |
|---|---|---|---|
| 线索 · 研究笔记 · 采访记录 | `2origin-scratch` | 🔒 **私有** | **无门槛，随手就写** |
| 现场报道 · 修正 · 书 | `2origin-marketing`（本仓） | 🌐 公开 | **过三道闸**（见下） |

### 从草稿本提取到本仓，必须过三道闸

1. **核实** —— 数字现跑现写 · 名字先 grep 查重 · 状态四选一（提案/原型/已实现/已发布）
2. **脱敏** —— 私有仓路径、客户信息、经营数据、竞品调研、个人联系方式，一律不出现
3. **标源** —— 【公开可核】读者自己能验 · 【内部可核】只有我们能重跑（**必须写出命令**）

**判断规则**：一段素材只有在**它本身就是 2Origin / U-King 公开叙事的一部分**时才能出去。
「它很有说服力」「投入很大」都不是理由——**投入越大越可能是核心生意，越不该公开。**

## 为什么要有这个岗

营销引擎的扫描器 `refresh-notes.mjs` 扫的是 **commit**。commit 是结果，是已经想明白、写下来、push 上去的东西。

但项目里最值钱的时刻不在 commit 里。**「本源总线该定义可继承的授权凭据」这句话诞生在一次对话中**——它此刻不在任何代码里、不在任何 RFC 里、没有 commit hash。按扫描器的逻辑，它要等到有人先把它实现了，营销才看得见它。

**那时候现场已经凉了。** 读者看到的是一个做好的功能，看不到它是怎么被想出来的——而后者才是别人抄不走的东西。

新闻官补的就是这个洞：**在东西进 git 之前先把它抓住。**

## 三种体裁

| 体裁 | 位置 | 什么时候写 | 特点 |
|---|---|---|---|
| **线索** | 🔒 `2origin-scratch/线索/` | 发现发生的**当场** | 原始、粗糙、不加工。宁可乱，不可漏。 |
| **现场报道** | `press/发现/` | 线索**过闸之后** | 成稿，写推理链条，走草稿制待审 |
| **修正** | `press/修正/` | 发现自己报错了 | 主动打脸。比不出错更有说服力。 |

线索**不是**稿子。线索的唯一任务是把当场的原话、时间、上下文钉住，防止三天后回忆成另一个样子。

## 铁律（这个岗特有的，AGENTS.md 通用规则之外）

### 1. 名字先查重 —— 建岗当天就栽在这

提出一个「新概念」时，**先 grep 自己全部仓库**，确认这个词是不是早就存在、且是不是另一个意思。

> **建岗当天的教训**：讨论中把「本源总线（OriginBus）」当成新发现。
> 一查 `RFC-0000` 第 58 行——它从第一天就在架构表里，指的是**北桥/高速总线**（把状态编译进 Context），
> 还是 `TRADEMARKS.md` 里的注册商标词。RFC-0000 第 175 行甚至已经写了「OriginBus Trust 层」。
> 真正新的是**把 Trust 层的责任从南桥改派给 Harness Adapter**，以及「凭据可继承」这个机制。
> 差一点就发出「今天发现了一个新东西」——读者打开 RFC-0000 一眼拆穿。

**查重命令**：`grep -r "你的新词" D:/uking编程/ --include=*.md`

### 2. 状态必须四选一，标在稿子里

| 状态 | 含义 | 能说的话 |
|---|---|---|
| **提案** | 只是个想法，没实现 | 「我们认为该有」 |
| **原型** | 有能跑的东西，没定型 | 「已有原型，尚未定型」 |
| **已实现** | 代码在，测试过 | 「已实现，N 个测试覆盖」 |
| **已发布** | 用户能用上 | 「你现在就能用」 |

**混淆这四档 = 骗人。** 提案说成已实现是最常见的死法。

### 3. 数字现跑现写

见 AGENTS.md「数据背书」。这个岗更容易犯，因为发现的当场情绪高、数字随口就来。

踩过的两种坏数字，**病因不同，必须分开处理**：

| | 例 | 病因 | 怎么防 |
|---|---|---|---|
| **虚构** | RFC-0001 的「43 条判据」 | 查无实据（实测 38 tests / 97 asserts，无一为 43） | 跑命令 |
| **腐烂** | 「772 条声明」 | 测量时为真，随后失效（21 分钟后已是 970，「仍成立」始终 8） | **写上跑的时刻，引用前重跑** |

**把腐烂当成虚构，对第二种不公平，还会丢掉最重要的洞见：
一个只累积声明、不重新验证的系统，它的「真」有半衰期。**

### 4. 热情不是证据

发现的当场一定很兴奋。兴奋是写作的燃料，不是事实的来源。
**稿子的说服力来自「我们连自己名字里已有的东西都要先查一遍」，不来自形容词。**

## 工作流

```
对话中发生发现
   ↓ 当场（🔒 私有仓，无门槛）
2origin-scratch/线索/YYYY-MM-DD-短名.md      ← 原话 + 时间 + 上下文，不加工
   ↓ 三道闸：核实 → 脱敏 → 标源
press/发现/YYYY-MM-DD-短名.md               ← 成稿，按 AGENTS.md 格式
   ↓
更新 STATE.md 草稿库 → git push
   ↓
等用户审 → 用户决定发不发
```

**发布权在用户，新闻官只到 push 为止。** 和其他草稿一样。

## 谁来干

- **对话当场记线索**：常驻会话的 Claude（发现发生时它在场，这是它唯一的不可替代性）
- **过闸 + 成稿**：每日班次（cron）或指派的 subagent
- **审稿发布**：用户
