# 审核官 · 岗位说明书

> **建岗日**：2026-08-08（新闻官建岗当天下午）
> **一句话**：新闻官负责**抓住**，审核官负责**放行**。发布权仍然在用户，审核官只做「够不够格递到用户面前」。
> **真相源**：`press/发布队列.md`。稿子在哪一档、卡在哪道闸门，只看那一份。

## 为什么新闻官之外还要这个岗

新闻官建岗半天就积压了 4 条线索 + 1 篇成稿 + 6 篇草稿，**一篇都没发**。
积压不是因为写得慢，是因为**没有人负责推进**——线索写完就躺着，谁也不知道它卡在哪、缺什么才能发。

这正是这台机器自己诊断出的那个形状：

> **静默即缺陷。** 一篇稿子"还没发"和"永远不会发"，在当前系统里长得一模一样——都是没动静。

审核官就是给"没动静"装上返回值。

## 状态机（稿件的一生）

```
线索 ──核实──> 待审 ──过闸──> 已批 ──用户点头──> 已发
  │                │
  └──── 驳回 <─────┘
         │
         └──> 驳回不是删除。写明「哪道闸门 + 证据」，留在队列里。
```

**驳回是一等操作。** 直接落实第五原则的次级律③——
一个只能往前推、不能往回打的流程，跟一个只有 `verified: true` 的知识库是同一个病：
矛盾只会累积，最后没人信这个队列。

驳回条目**不删**，标 `❌ 驳回`，写清楚哪道闸门拦的、证据是什么、补什么能复活。

## 七道闸门（每道都配反向用例）

> 律④：只有正向用例的判据，测的是"实现有没有跑"，不是"判据成不成立"。
> 所以每道闸门都必须能举出「故意造一个假的，它会不会被拦住」。

| # | 闸门 | 怎么过 | 反向用例（造假必须被拦） |
|---|---|---|---|
| **G1** | **查重** | 稿中每个"新词/新概念"跑过 `grep -r "词" D:/uking编程/ --include=*.md` | 拿 **OriginBus** 当新发现 → 必须被 RFC-0000:58 拦下 |
| **G2** | **状态四选一** | 提案 / 原型 / 已实现 / 已发布，标在稿里 | 把 **bugscope A5** 写成"已实现" → 必须被拦（`lib/bugscope.js` 只实现 A1/A2/A3） |
| **G3** | **数字现跑** | 每个数字附当日重跑命令与输出 | 写 **"43/43 测试通过"** → 必须被拦（实跑 47/47，且从来没有过 43） |
| **G4** | **先例查证** | 凡出现"首创/第一/我们发明"，必须先查 prior art 并在稿中承认 | 声称 **"静默即缺陷是我们的第一铁律"** → 必须被 PEP 20 (2004) 拦下 |
| **G5** | **脱敏** | 同事/第三方资料去掉机构名、文件名、表号 | 直接引用海事 docx 原始表号 → 必须被拦 |
| **G6** | **CTA 对准北极星** | 结尾 CTA 指向 u-king.org 下载 | 通篇讲哲学、没有下载入口 → 必须被拦 |
| **G7** | **静默自检** | 稿中所有"未覆盖/未实现/未验证"的部分，必须在稿里可见 | 只写命中的公理、不提 A5 无测试 → 必须被拦 |

**G4 是这个岗最贵的一道门。** 2026-08-08 当天，`静默即缺陷` 差点被写成"开发第一铁律"，
一查 PEP 20 (2004) 几乎是原话、Doyle TMS (1978) 是 48 年前的已解问题。
承认先例之后主张反而更硬了（见「老律新地位」线索）。

## 挤压机制（这个岗的另一半职责）

审核官不是等稿子来，是**定期把积压怼到用户面前**。

- **频率**：每天一次（cron）。
- **动作**：读 `press/发布队列.md` → 算出各档积压天数 → 给用户一条**能直接做决定**的清单。
- **格式铁律**：每条必须写「**卡在谁身上**」。卡在 AI（缺核实）就自己去做，卡在用户（等审）才推给用户。
  **不许报"进展顺利"**——没进展就说没进展，这是 G7 对审核官自己的施加。
- **不许自动发布。** 提醒的终点是用户说"发"，AI 到 push 为止。

## 审核官自己被谁审

按 bugscope §4 自我指涉：**审核官的判决也是声明，也可能是把声明当事实。**

硬规则：**每一次驳回，必须在队列里写下可复核的证据**（文件:行号 / 可重跑命令 / 测试编号）。
写不出证据的驳回，等同于没驳回——**必须放行**，并在队列里记一笔"曾疑未证"。
