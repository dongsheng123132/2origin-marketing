## 上下文

在分析本境协议、讨论「授权/批准」这层该谁管的时候冒出来的。
背景是 RFC-0006（北桥标准接口 + 南桥信任模型）刚落地（`fb513bc` / `6b01c6f`，同日）。

## 原话（未加工，勿改）

> ③ 真正属于 2Origin 的空位 —— 这个别人不会替你做
>
> MCP 的 elicitation 只覆盖「这一次调用要不要问人」。你要的是更上一层：授权凭据在层间可继承——南桥算出的 risk 和它接受的凭据，要能沿 Harness → Adapter → 南桥 这条链传递并被上游理解。
>
> MCP 没有，A2A 没有。这是本源总线（OriginBus）该定义的东西，也是 2Origin 在 RFC-0000 §1 声明的那个"更高一层"真正落到实处的第一个地方。
>
> 而且你手上已经有原型了：expect_sha256 = "证明你读过当前内容"。它比"你被批准了"强——无头 agent 拿得出，没读过的拿不出，而且顺手解决静默覆盖。43/43 验证过。这是能直接拿去当提案的资产，不是概念。
>
> 一句话
>
> 不是南桥的责任，是 Harness Adapter 的责任；Adapter 之上那层可继承的授权凭据，才是 2Origin 该发明的东西。

## 当场核实（2026-08-08，成稿前做的）

### ❌ 「本源总线（OriginBus）」不是新词

- `rfcs/RFC-0000-2origin-computer.md:58` — `| 高速总线 | 北桥 | **OriginBus** | 把相关状态编译进 Context |`
- `TRADEMARKS.md:12` — 列为商标：`本源北桥 / 本源南桥 / OriginBus / OriginBoot`
- `README.md:35` / `RFC-0000...en.md:57` — 同样定义

**它从第一天就存在，且指的是北桥（状态→Context），不是授权。**

### ⚠️ 「OriginBus Trust 层」也已经写过，而且原本派给的是南桥

- `RFC-0000-2origin-computer.md:175-176` — 「跨 harness 真正缺的不是状态格式，而是 **OriginBus Trust 层的统一写授权**……这是"南桥"/ Trust Plane 的职责，本架构将其列为必建组件」
- `RFC-0000-2origin-computer.en.md:165-166` — 英文版标了 `SOLVED ✅`，用南桥 MCP server（`southbridge_write`）解决

### ✅ 真正新的东西在这里（线索的价值点）

不是 OriginBus 这个名字，是**两处改动**：

1. **责任改派**：Trust 层从「南桥的职责」（RFC-0000 原文）改派给 **Harness Adapter**
2. **新机制**：Adapter 之上要有一层**可继承**的授权凭据——沿 `Harness → Adapter → 南桥` 传递并被上游理解

第 2 点是 MCP elicitation 和 A2A 都没覆盖的（待独立核实，见下）。

### ❌ 「43/43 验证过」是错的

- 实跑 `npm test`（2origin-harness，隔离）：**38 tests · 38 pass**
- 同日上午同一套是 **34/34**，RFC-0006 落地后 +4 → 38
- **从来没有过 43**
- 且 `expect_sha256` 只 grep 到 1 条专项测试：`ok 3 - 乐观锁：expect 不匹配则拒绝写（conflict）`
- 正确说法：「乐观锁有专项测试覆盖，整套 38 个测试全过」
