<h1>它终于说了「否」，但没人知道否的是谁</h1>

<p>前天我们统计过自己那台 AI 计算机的「学历」——它跨会话攒下来的、每条都带证据来源的已验证事实。</p>

<p>当时的数字是：<strong>204 条事实，204 条为真，0 条被推翻。</strong></p>

<p>我们当时写道：这不是因为它从没错过，而是因为它的真值模型里根本没有「否」这个取值。</p>

<p>今天重新跑了一遍：</p>

<pre><code>学历 17 份
facts        386
verified=true 371
verified=false 15   ← 新出现</code></pre>

<p><strong>它开始说「否」了。</strong>一天之内，从 0 条变成 15 条。</p>

<h2>但问题没解决，只是换了个形状</h2>

<p>翻开那 15 条「否」，它们的字段只有三个：<strong>claim（说了什么）、verified（真假）、when（什么时候）。</strong></p>

<p>没有 <code>refuted_by</code>。没有任何字段指向「我推翻的是哪一条」。</p>

<p>所以现在的状态是：<strong>推翻的和被推翻的，仍然并排躺在同一个列表里，只是其中一条的布尔值翻了个面。</strong>两者之间没有链接。每一个新会话打开这份学历，还是要重新裁决同一场官司——只不过这次两边的说法都在，且都不知道对方存在。</p>

<p>换句话说：<strong>「否」被说出来了，但它没有对象。</strong></p>

<h2>今天还查出一处更不对称的地方</h2>

<p>写入一条事实的函数是开源的，可以自己去看。它长这样：</p>

<pre><code>export function addFact(state, claim, source, verified = true) {
  if (verified) {
    const rc = recheckSource(source);
    if (!rc.ok) throw new Error('fact source 不可复核');
  }
  ...
}</code></pre>

<p>看那个 <code>if</code>。</p>

<p><strong>你说「这是真的」，系统会检查你的证据来源是不是可复核，不合格直接拒收。</strong></p>

<p><strong>你说「这是假的」，什么都不检查。</strong></p>

<p>立「是」要证据，立「否」不要证据。<strong>一个如此严格要求正面主张必须可核验的系统，对否定主张完全不设门槛。</strong>这解释了那 15 条为什么连 <code>source</code> 字段都是空的——它们从来不需要有。</p>

<p>这不是小疏漏。<strong>它意味着「推翻」在这套设计里始终不是一等操作</strong>：不需要证据、不需要指向对象、不需要留下审计痕迹。它只是把一个布尔翻了个面。</p>

<blockquote><p><strong>推翻必须是一等操作，与写入同等待遇。</strong><br>没有 <code>refuted_by</code> 的知识库，不是知识库，是留言板。</p></blockquote>

<h2>说清楚现在到哪一步</h2>

<p>这条律<strong>已经写进了架构纲领</strong>。但机制<strong>还没有实现</strong>——搜遍参考实现，<code>refuted_by</code> 零命中。所以它现在的准确状态是<strong>提案</strong>：律文在纲领里，能力不在代码里。<strong>我们没有做出推翻机制，只是承认了需要它。</strong></p>

<p>而且这条律不是我们发明的。纲领里自己写着：</p>

<blockquote><p>Truth Maintenance System（信念挂 justification，支撑一旦撤销、信念自动退出）—— Jon Doyle, MIT AI-TR-419, <strong>1978</strong>。<br>「推翻必须是一等操作」是 <strong>48 年前的已解问题</strong>。<strong>修法应当抄 TMS，不要自己发明。</strong></p></blockquote>

<h2>顺带：另一条同批提出的律，这两天被做出来了</h2>

<p>同一批诊断里还有一条：<strong>「学历必须有代谢」——一台只能记不能忘的机器，最终会被自己的历史压垮。</strong></p>

<p>前天查的时候，整个仓库里跟「遗忘」相关的实现是零。今天它有了：<strong>已验证的条目带保鲜期，超期又没被重新用到的会自动降级，不硬删、保留证据，但不再作为有效学历装载进上下文。</strong></p>

<p>两条律同一天提出，两天后一条已实现、一条仍是提案。<strong>把它们放在一起说，是因为只报好消息那半边，就是这套方法论自己要抓的病。</strong></p>

<h2>为什么把这些发出来</h2>

<p>因为「0 条被推翻」看起来像是从不犯错，而<strong>「从不犯错」这个观感本身，就是缺陷在起作用</strong>。</p>

<p>现在它会说「否」了，看起来像是修好了。<strong>但一个不需要证据、也不指向对象的「否」，只是把静默换成了噪声。</strong></p>

<p>顺带说一句：这些数字每天都在动，两天内 96 → 204 → 386。所以每个数都标了跑的时刻——不标时刻的数字，过一夜就成了下一个错误。这篇文章的初稿就是这么作废的：它写着「0 次否」，一天后就不成立了。<strong>我们没有删掉那句话，而是把它作废的过程写进了正文。</strong></p>
