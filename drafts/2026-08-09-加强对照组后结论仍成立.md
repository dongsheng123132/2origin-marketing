<h2>上一版的对照组，是个稻草人</h2>

<p>我们之前做过一次对比：同样的预算，喂结构化状态 vs 喂对话流，看模型能不能接着干活。结果差距很大。</p>

<p>但那一版的对照组只有一种做法——<strong>把对话记录从尾部截断</strong>。这不公平。真实的 Agent 框架不会这么干，它们会做摘要（compact），会做检索（RAG）。</p>

<p>拿最弱的做法当对手，赢了也不算数。所以这一版我们给对照组换上了更强的武器。</p>

<h2>六个臂，同一份预算</h2>

<p>对照语料是两份真实的 Claude Code 会话记录（3.0MB + 2.5MB，按字节钉死，避免每次跑的语料不一样）。除 10 倍预算那一臂外，各臂喂进去的字符数相同（9,635 字符）。</p>

<ul>
<li><strong>2origin</strong>：本境编译出的结构化状态</li>
<li><strong>summary</strong>：模型生成的摘要，分段摘要再合并，模拟 <code>/compact</code></li>
<li><strong>rag</strong>：BM25 词法检索（CJK 二元组），逐题各检索一次</li>
<li><strong>transcript</strong>：对话流尾部截断</li>
<li><strong>transcript-10x</strong>：同上，给 10 倍预算</li>
<li><strong>none</strong>：空上下文，地板线</li>
</ul>

<h2>结果</h2>

<p>模型 <code>deepseek-v4-flash</code>，temperature 0，79 题/臂，474 次调用、0 错误 0 截断。</p>

<p>换上摘要和检索之后，对照组确实比原来强了一点。但差距仍然在。</p>

<h2>更多 token，反而更差</h2>

<p>最值得看的是 <code>transcript-10x</code>：它用了将近 8 倍的输入 token，事实召回却是全场最低的 35.0%。</p>

<p>不是 token 不够，是形态不对。把更多的聊天记录塞进去，模型要在噪音里翻找；而结构化状态是已经整理过的结论。</p>

<h2>一道我们自己撤回的题</h2>

<p>这一版我们新加了「两跳题」——问模型「这条已验证事实和这条下一步，是不是同一个任务的」。设计意图是绕开「答案字面写在状态里」的开卷效应，逼它做关联。</p>

<p><strong>它失败了。</strong></p>

<p>六个臂全落在 58.0%–71.4% 之间，Wilson 95% 区间大面积重叠。更要命的是：空上下文那一臂 63.8%，2origin 64.3%，只差 0.5 个百分点。</p>

<p>诊断下来，这题可以靠「这两段文字看起来是不是一个话题」蒙对，不需要任何状态——同一个任务的事实和待办本来就共享词汇。它测的是主题相似度，不是状态归属。</p>

<p><strong>这条指标作废，不用来支持任何结论。</strong>它留在结果表里只为透明。「开卷天花板」这个问题仍然没解决，留给下一版。</p>

<h2>所以现在能讲什么，不能讲什么</h2>

<p><strong>能讲的</strong>：结构化状态能给出近乎完美的事实召回，而且省将近 8 倍 token；这个结论在对照组换上摘要和检索之后仍然成立。</p>

<p><strong>不能讲的</strong>：不能说「状态让模型推理更好」。我们为此设计的题目失败了，还没有证据。</p>

<p>另外要说清楚的边界：单模型、单目标任务、单次运行，没做多次重采样；四选一那一列 n=15，Wilson 区间不窄，别把它当铁证。</p>
