<h2>一个我们一直没回答的质疑</h2>

<p>我们做的这套东西，核心主张是：<strong>让 AI 写长篇内容时不靠上下文硬记，靠一份可查询的世界状态。</strong>人物在哪、谁拿着什么、哪条伏笔埋到第几章，全部写在结构化状态里，不指望模型自己记住。</p>

<p>基准测试跑下来，带状态的那条臂确实更稳。但有一个质疑我们一直答不上：</p>

<blockquote><p><strong>这收益，会不会只是因为你们让模型多写了个 JSON？</strong></p></blockquote>

<p>这个质疑很致命。因为「要求模型每章输出一份状态快照」这件事本身，就可能逼它把注意力放在一致性上——那跟我们那套协议（上下文编译、证据链、校验退回）一点关系都没有。</p>

<h2>所以我们把这条质疑做成了一条对照臂</h2>

<p>新增的 <strong>A2 臂：纯提示词状态维护</strong>。它拿到的东西和我们自己那条臂<strong>完全一样</strong>——同一份世界规则、同一批禁区、同一个初始状态。</p>

<p>但它<strong>刻意</strong>被拿掉了三样东西：</p>

<ul>
  <li><strong>没有上下文编译器</strong>——状态和规则原样塞进提示词，最近正文只做最朴素的尾部截断</li>
  <li><strong>没有事务与证据链</strong>——每章直接重写一份完整状态，不要求它交代凭什么这么改</li>
  <li><strong>没有校验与退回</strong>——模型输出无论对错都只调用一次，<strong>不重试</strong></li>
</ul>

<p>换句话说，A2 就是「只要求写 JSON，别的什么都不给」。<strong>如果 A2 的成绩和我们那条臂差不多，那我们这套协议就是白干的。</strong></p>

<p>这条臂不是用来赢的，是用来输的。</p>

<h2>现在跑到哪一步了：只有冒烟，没有正式结果</h2>

<p>这里必须说清楚，因为很容易被写成比实际更好看：</p>

<ul>
  <li>✅ <strong>实现与自测已完成</strong>，自测进了 <code>npm run verify</code> 的常规链路</li>
  <li>✅ <strong>跑通了一次冒烟</strong>：固定模型快照、<strong>单轮</strong>，5 个状态快照全部完成</li>
  <li>⬜ <strong>正式消融还没做</strong>——需要 10 轮 × 2 个模型，还在待办里</li>
</ul>

<p>那次冒烟的结果，我们在自己的 README 里标的是<strong>「只作 pilot，不并入论文统计」</strong>。一轮就是一轮，它证明链路能跑通，<strong>不证明任何比较结论</strong>。</p>

<p>所以这篇文章没有任何「A2 比我们差多少」的数字。<strong>没跑就是没跑。</strong></p>

<h2>顺手改掉一处对别人不公平的标注</h2>

<p>做这一版之前，A2 那一格填的是另一个东西：开源项目<strong>「天命」</strong>（<a href="https://github.com/zy-zmc/tianming-novel-ai-writer">zy-zmc/tianming-novel-ai-writer</a>，MIT 协议），我们当时把它写成「已知最强先行者」并当作对照。</p>

<p>这个标注有问题。天命走的是<strong>状态 + 门禁</strong>的路线，它「不靠上下文、靠状态」的主张跟我们高度一致，是这条路上重要的先行工作——<strong>但它不是我们的 A2</strong>。A2 专指「不带门禁的 prompt-only 消融」，是我们自己设计的一条对照，跟人家的实现是两回事。</p>

<p>把别人的开源项目当成自己的消融臂，既不准确，对人家也不公平。这一版把两件事分开写了：致谢归致谢，消融归消融。</p>

<h2>为什么这件事值得单独写一篇</h2>

<p>做基准测试最省事的做法，是把对照组配得弱一点。分数会很好看，而且几乎没人查得出来。</p>

<p>A2 是反过来的：<strong>我们主动造了一个最可能打平我们的对照</strong>，并且在它跑出正式结果之前，一个字的比较结论都不写。</p>

<p>能让自己输的那条臂，比能让自己赢的那张图值钱。</p>
